## 1. Shared Clock and Data

The **Inter-Integrated Circuit (I²C)** bus uses serial data **SDA** and serial clock **SCL**. [Open-drain](<../DigitalGeneral.md#output-architectures>) outputs pull a line low. Pull-up resistors produce the high level.

A controller starts a transaction and sends an address. The addressed target acknowledges supported transfers.

## 2. Transfer Sequence

1. A **START** happens when SDA falls while SCL is high.
2. The controller sends the address and direction bit.
3. Each byte has eight bits, followed by an acknowledgment clock.
4. A **STOP** happens when SDA rises while SCL is high.

Data remains stable while SCL is high, except for START and STOP conditions. A repeated START can retain control between transaction phases.

Check whether an address is written as the 7-bit device address or as the full address byte, which also includes the read/write direction bit. Confusing them sends a transaction to the wrong address.

## 4. Worked Example

**Assumptions:** Supply is 3.3 V. Bus capacitance is 200 pF. Required rise time is at most 300 ns.

Assume each device supports 3 mA at a low voltage of 0.4 V.

1. Minimum resistance is about **967 Ω**.
2. Maximum resistance is about **1770 Ω**.
3. A nominal **1.5 kΩ** resistor gives about **254 ns** rise time.
4. At 0.4 V low, resistor current is about **1.93 mA**.

Include [resistor tolerance](<../../01-Discrete-Components/01-Passives/01-Resistors.md#2-tolerance-and-temperature>) and capacitance uncertainty. Parallel pull-ups on multiple boards reduce the effective resistance.

## 5. Fault Checks

Check duplicate addresses, startup states, and recovery when a line stays low. Also check clock stretching, where a target holds the clock low until it is ready. A controller that ignores this can move on before the target is ready.

Measure rise time at the most heavily loaded point. Confirm both high and low voltages.

**References:** [NXP, I²C bus specification](https://www.nxp.com/docs/en/user-guide/UM10204.pdf), [TI, pull-up calculation](https://www.ti.com/lit/pdf/slva689).


## Address capacity, arbitration, and recovery

Seven address bits provide 128 patterns, but reserved groups reduce the ordinary target addresses. Device address options and bus capacitance impose further limits.

Address pins, programmable addresses, or an I²C multiplexer can resolve collisions. A fixed-address device cannot adopt an arbitrary address without explicit support.

On a bus that supports multiple controllers, each transmitter also watches SDA. If it releases the line for a high but sees a low, another transmitter has priority at that bit. It loses arbitration and stops transmitting.

A receiver sends a negative acknowledgment after the final read byte to end data reception. An unexpected negative acknowledgment earlier can indicate another condition.

Standard-mode supports up to 100 kbit/s, Fast-mode 400 kbit/s, and Fast-mode Plus 1 Mbit/s. Faster modes have additional requirements.

If SDA remains low, up to nine clock pulses can let a target complete its byte. Check SCL release and use the documented reset path if recovery fails.

See the [NXP I²C specification](https://cache.nxp.com/docs/en/user-guide/UM10204.pdf) for reserved addresses, mode limits, and bus-clear conditions.

Reducing pullup resistance usually shortens rise time, which makes the edge faster. Excessive pullup current can prevent a target from reaching a valid low voltage.

Increasing resistance makes the rise slower. Added devices, long traces, connectors, and probes can increase bus capacitance.
